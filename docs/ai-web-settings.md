# 웹 AI 호출 설정

로그인 후 프로젝트 작업실 상단의 **AI 호출 설정**에서 API 모델 ID, 추론 effort, 출력 토큰 한도를 바꾸고 저장합니다. 16,000 / 32,000 / 64,000 / 128,000 빠른 선택과 정수 직접 입력을 지원합니다. 실제 사용 가능한 최대값/effort는 해당 API 모델이 결정하며 프로그램은 지원하지 않는 값을 다른 값으로 몰래 바꾸지 않습니다.

첫 값은 서버의 URS_OPENAI_MODEL / URS_OPENAI_REASONING_EFFORT / URS_OPENAI_MAX_OUTPUT_TOKENS에서 읽습니다. 출력 한도 환경변수가 없거나 비어 있으면 이전과 같은 5,000입니다. 웹에서 저장한 직원별 값이 그 직원 문서의 다음 호출부터 우선 적용됩니다. **웹 설정 저장 후에는 서버 재시작이 필요 없습니다.** 이 기능의 새 코드 설치 시에는 최초 1회 서버를 재시작해야 합니다.

설정은 새 ai_settings 테이블에 버전별로 추가 저장합니다. 다른 직원 설정, 기존 프롬프트, 보고서/원본/검증 기록을 덮어쓰거나 지우지 않습니다. 진행 중인 요청은 시작 시의 모델/effort/토큰 한도 스냅샷을 계속 사용합니다. 기존 보고서는 자동 재생성하지 않습니다.

실제 Responses API의 model, reasoning.effort, max_output_tokens에 연결합니다. effort를 API 기본값으로 저장하면 환경변수에 effort가 있더라도 요청 필드를 생략합니다. 새 출력 한도는 보고서 및 별도 독립검증/기술분석 요청과 문서별 비용 예약 계산에도 적용합니다. 예산과 단가는 기존 서버 설정을 사용하며, 모델을 변경해도 단가를 자동 추정하지 않습니다.

API 키는 이 화면에서 표시/저장하지 않고 기존 서버 비밀 설정을 유지합니다. 설정 조회/저장은 로그인 및 POST의 CSRF 검사를 거칩니다. 저장 동작은 유료 API를 호출하지 않습니다.

모델 HTML 원문/최종 HTML은 그대로 보관합니다. 결과 화면에는 해당 보고서를 만들 당시의 모델·effort·출력 한도가 표시됩니다. 현재 설정과 이전 검증의 설정이 다르면 이전 검증을 최종 승인에 재사용할 수 없습니다.

출력 토큰에는 모델의 추론 토큰이 포함될 수 있습니다. max_output_tokens로 응답이 incomplete가 되면 출력 한도와 AI 호출 설정 안내를 단계 오류에 표시하며, 성공으로 처리하거나 자동 유료 재시도하지 않습니다.

진단 명령 check_api_report.py도 선택 문서 직원의 웹 저장 설정을 우선 사용합니다. 실제 응답 모델/effort/출력 완성 여부는 실제 API 결과로만 판정합니다.

개발 검증: 임시 DB/모의 API로 실제 요청 필드, 직원 격리, 재시작 후 보존, 입력 검증, 비용 보호, 도중 변경 시 설정 일관성, 기존 HTML 보존, 인증/CSRF/비밀 비노출을 시험합니다. 실제 Chromium에서 폼/빠른 선택/저장/새로고침/반응형을 확인합니다. 실제 유료 API 호출은 이 변경 시험에 포함하지 않습니다.
