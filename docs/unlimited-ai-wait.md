# 모든 OpenAI 응답 무제한 대기

HTML 보고서 생성만 대기시간을 조정했던 이전 경로와 달리, **독립검증·기술분석에도 남아 있던 고정 90초를 제거**합니다. 무료 입력 토큰 계산도 같은 정책을 사용합니다. 모든 OpenAI HTTP 연결에 `timeout=None`을 명시해 앱의 소켓 대기 한도를 없앴습니다. 임의의 매우 큰 숫자로 대신한 것이 아닙니다.

기존 `.env`의 `URS_OPENAI_REPORT_TIMEOUT_SECONDS`와 `report_timeouts`의 900/1000초 등 저장값은 이력으로 보존하지만 실제 대기 한도로 사용하지 않습니다. DB를 초기화하거나 이전 값·실패 기록을 수정하지 않습니다. 옛 설정 API의 유한 값 입력은 호환 이력으로만 남으며, 반환값은 `timeout_seconds:null`, `unlimited:true`, `legacy_value_applied:false`입니다.

웹의 초 단위 입력/저장 폼은 **무제한 · HTML 보고서 생성·독립검증·기술분석·무료 비용 계산 전체 적용** 안내로 바꿨습니다. 구버전 서버 응답이면 무제한이라고 표시하지 않고 재시작이 필요하다고 안내합니다. 과거 90초 실패는 당시 실행 기록으로 구분합니다. 이미 끝난 실패를 재시도하거나 새 유료 요청을 자동 실행하지 않습니다.

각 작업은 기존 백그라운드 실행·상태 조회를 유지합니다. 응답이 오기 전에 앱이 90/600/900초를 이유로 중단하지 않습니다. OpenAI가 완료/불완전/실패 응답을 주거나 연결이 끊기는 경우는 별도로 처리합니다. 무제한은 OpenAI·프록시·네트워크·실행 서버의 연결 유지 자체를 보장하는 뜻은 아닙니다. 외부/네트워크 시간 초과 예외가 들어오면 내부 90초 제한으로 오인하지 않도록 기록하고, 자동 유료 재시도하지 않습니다.

보고서 요청 진단과 검토 기록에는 `timeout_seconds:null` 또는 `api_timeout_seconds:null`, `timeout_policy` 또는 `api_wait_policy:unlimited`를 남깁니다. 실제 경과 시간, HTTP/응답 상태·사용량 기록은 유지합니다. 출력 토큰 한도·모델·effort·프롬프트·사진 삽입·비용 계산/정산·기존 보고서는 이번 변경으로 바꾸지 않습니다. HTML 렌더링 검사·서버 기동 확인·DB 잠금의 별도 내부 제한은 OpenAI 응답 대기와 다르며 이번 변경 대상이 아닙니다.

모의 시험은 생성/독립검증/기술분석/무료 토큰 계산의 실제 어댑터 연결 kwargs가 모두 None인지 검사합니다. 이전 900초 설정이 남아 있어도 동일합니다. 서버는 접수 뒤 계속 running 상태를 조회할 수 있고, 완료 응답을 받은 뒤에만 결과를 저장합니다. 오류 시 기존 파일·사용 기록 보존도 시험합니다. 유료 호출이나 운영 문서 재실행은 하지 않았습니다.

적용: `git pull && python start.py` 후 웹을 새로고침합니다. 실행 중이던 구버전 Python 프로세스의 코드는 파일을 내려받기만 해서는 갱신되지 않으므로 서버 재시작이 필요합니다. 소스 푸시를 운영 서버 적용 완료로 보고하지 않습니다.
