# 직원용 보고서 열람과 PASS 안내

## 버튼과 파일

보고서 검토 상단의 ‘직원용 최종 보고서’ 구역에 기본 버튼 하나를 배치했습니다. ‘최종 보고서 보기(사진 포함)’은 selected 저장 버전의 report.html을 미리보기로 엽니다. 바로 옆에 파일명·버전·짧은 SHA-256을 표시하고 상세 메뉴에서 전체 URL·해시를 볼 수 있습니다. ‘사진 포함’은 직원용 최종 결과물의 용도를 뜻하며, 사진 상태 진단과 실제 미리보기를 별도로 제공합니다.

위쪽 ‘최종 HTML’은 파일을 여는 버튼이 아니라 구역 이동 앵커였으므로 ‘직원용 보고서 구역’으로 이름과 위치를 명확히 했습니다. report.html 다운로드, Terra의 이미지 연결 전 report.raw.html, 진단용 저장 HTML/API 응답 묶음 ZIP을 접힌 상세 메뉴에 모았습니다. 검증·실행 이력 HTML/JSON도 보고서와 다른 파일임을 이름으로 구분합니다. 진단 ZIP은 현재 보고서와 다른 최근 실패 이력을 가리킬 수 있어 그 버전을 표시합니다.

독립검증 결과의 보고서 링크는 ‘검증에 사용한 직원용 보고서 보기 · 버전 N’입니다. 검증 대상과 현재 직원용 버전을 상단에 함께 표시합니다. 수정된 보고서가 생기면 과거 링크는 ‘수정 전 검증대상’으로 표시하고 새 보고서 링크를 노출합니다. 현재/검증 대상이 같은 동안 중복 보고서 링크를 숨깁니다. 자동 스크롤을 즉시 이동으로 바꿔 화면이 움직이는 중 다른 조작을 누르게 되는 현상을 막았습니다.

## 기존 파일 사진과 새 생성 기능

읽기 전용 staff_report 정보는 실제 선택된 report.html bytes에서 내장 img 개수·미연결 원본 URI·PDF 파일 선택 입력·인식된 숨김 CSS와 ready 대기 구조를 확인합니다. 이는 정적 진단이며 실제 브라우저 가시성을 확인했다고 표시하지 않습니다. 사진 데이터가 있는데도 숨겨질 수 있다는 것과 사진 자체가 없는 것을 구분합니다. 기존 파일은 어떤 내용도 바꾸지 않습니다.

과거에 받은 실제 고객 HTML을 비공개 임시 DB에 그대로 넣고 현재 URS 버튼으로 읽는 경로를 재현했습니다. 저장 bytes와 HTTP로 열린 bytes의 해시 일치, 원문 9·23쪽 그림의 embedded 데이터와 display:none을 확인했습니다. 사용자가 운영 결과 화면에서 공유한 현재 보고서 링크는 revision=1이며, 저장 최종 HTML 지문은 이 재현에 사용한 파일과 일치합니다. 직접 운영 로그인으로 응답 bytes를 읽은 것은 아니므로 운영 브라우저 확인과 구분합니다. 고객 파일/스크린샷은 공개 저장소·패키지에서 제외했습니다.

새 생성 경로의 자동 이미지 연결/레거시 로더 정리와 기존 저장본의 표시 문제는 별개입니다. 이 패치는 기존 report.html을 교체하거나 새로 생성하지 않습니다.

## 실행과 PASS

실행 선행 조건은 저장 보고서 접근/무결성, 같은 문서의 동시 작업 여부, 요청 횟수 및 실행 전 API 설정·무료 비용 계산·회당 상한 확인입니다. 선행 조건에 통과하거나 실행 버튼이 활성이라는 것만으로 PASS가 아닙니다.

현재 코드에서 해당 보고서의 검증이 정상 완료되고 응답 status가 PASS이며 issues 배열이 비어 있어야 통과합니다. PASS와 비어 있지 않은 issues 응답은 거절합니다. 고객 확인 또는 프로그램 문제를 번역 오류 수에서 분리한다고 해서 통과 조건에서 임의로 면제하지 않습니다. 최근 실행 실패와 이전 저장 결과도 따로 표시합니다.

담당 직원이 확정 번역 오류를 원문과 대조해 수정하고 새 버전으로 저장한 후 그 새 보고서를 재검증해야 합니다. 고객 확인은 담당 직원이 고객/RFQ 책임자에게 원문의 적용 기준을 확인해야 합니다. 현재 웹에는 고객 답변·근거를 저장하고 검증 입력에 연결하는 전용 기능이 없습니다. 다른 메모 칸에 쓰면 해결된다고 안내하거나 체크만으로 PASS 처리하지 않습니다. 프로그램 문제는 개발/운영 담당자가 실제 직원용 HTML과 요청 해시로 재현한 검증 사본을 대조해야 합니다.

## 시험과 범위

기존 저장 파일을 직접 시드한 임시 DB에서 실제 로그인 버튼을 눌러 파일 열기/다운로드를 확인합니다. 이 시험은 생성/검증 API를 호출하지 않습니다. 미리보기와 최종 다운로드는 동일 bytes, raw 다운로드는 다른 bytes임을 확인합니다. 9쪽 벡터 도면과 23쪽 두 사진이 내장돼 있지만 숨겨진 합성 저장본을 열고 이력/파일이 변경되지 않는지도 확인합니다.

별도 단위 시험은 지문·경로, can_run과 NEEDS_REVIEW 차이, 최신 실패와 이전 결과 구분, 기록 기능 부재 표시, 읽기 부작용 없음과 이미지 상태 구분을 확인합니다. 기존 수정/재검증 브라우저 시험도 유지합니다. 실제 고객 문서의 새 생성·외부 A4 업로드·유료 재검증·운영 DB 변경은 실행하지 않았습니다. 운영 화면 직접 조회는 여전히 미확인입니다.

새 정적 UI만 갱신되고 구버전 Python 서버가 실행 중인 경우도 모의 시험합니다. staff_report 진단 응답이 없으면 기존 저장본을 없다고 표시하지 않고, 파일·버전·열람 기능은 유지하면서 진단 정보 미지원/재시작 필요를 표시합니다. 검증 결과에는 검증 대상 버전과 현재 직원용 버전을 함께 표시하고, 번역 오류가 없는 결과의 수정 패널은 숨깁니다.

사용자 제공 기존 결과는 번역 오류 0건·고객 확인 6건·프로그램 점검 1건입니다. 원문 7쪽의 4시간/2시간 적용 조건과 8쪽의 설비 명칭 적용 대상은 고객 확인 사항입니다. 나머지 고객 확인 4건의 세부 내용은 제공되지 않아 추정하지 않습니다. 직원용 파일에는 data:image가 들어 있으나 urs-image를 찾는 옛 스크립트와 숨김 CSS가 남습니다. 검증 사본의 urs-review-image 주소는 별도 전송용 식별자이며, 과거 실제 사본 해시가 없으므로 당시 전송 bytes는 미확인입니다.

최종 확인: 단위·HTTP 233개, 실행기 11개 모두 exit code 0. 현재 소스 90개·증거 42개 해시가 validation-summary.json과 일치합니다.
