# 실제 API/HTML 진단 명령 추가 (2026-11-16)

`python scripts/check_api_report.py`는 같은 서버의 .env 로딩 규칙 및 현재 직원/최근 PDF의 저장 프롬프트 유무·모델 설정·기존 호출 기록을 읽습니다. API 키, 프롬프트/PDF/HTML 본문은 출력하지 않습니다.

## 최종 완료에 필요한 외부 조건

1. API 연결은 사용자 지시에 따라 보류했다. 사용자가 이미 키 등록/변경을 했다고 확인했으며, 같은 키의 재입력이나 캡처를 요구하지 않는다. 실제 호출 시에는 실행 환경의 연결 조건이 충족돼야 하지만 현재 개발 작업은 이 조건을 기다리지 않고 진행한다. 보류를 API 검증 PASS로 처리하지 않는다.
2. 회사/고객이 사용을 승인한 대표 실제 URS PDF와 전문가 원문 대조 자료가 필요하다. 영어·인도네시아어, 표·그림·스캔·안전 조건 등 실제 사용 범위를 포함해야 한다.
3. 실제 OpenAI 응답으로 번역/검증/수정/분석을 실행하고, 원문 및 출력 4개를 전문가·직원이 대조한다. 전문가 평가를 현재 코드·고정 모델에 연결해 99% 이상·중대 안전 오역 0건을 입증한다.
4. 실제 문서의 미해결 오류가 0이 되고 출력 검토/직원 승인을 통과한 뒤 최종 업무 완료를 판정한다. 로컬 개발 서버 검증은 외부 배포/게시 검증이 아니다.

무선 표·특수 레이아웃·문자 없는 빈 페이지 등 현재 자동 판독으로 확정할 수 없는 문서는 검토/차단 대상으로 남는다. 위 외부 조건이 있어도 새 오류가 발견되면 수정·재시험하며 자동으로 완료라고 처리하지 않는다.


## API 연결 보류 후 후속 작업

- `120mm`처럼 단위에 붙은 숫자와 문장 끝 숫자의 변경 누락을 보강했다.
- 숫자/단위가 각각 같아도 서로 잘못 짝지어진 번역을 탐지한다. 한국어/인도네시아어 단위 표기 대응과 SI 접두사의 대소문자 차이를 검증한다.
- 같은 단위의 수치를 서로 다른 제품에 바꿔 붙이는 경우, 조건/부정/의무/순서의 오역은 여전히 별도 문장 의미 검증이 필요하다. 새 결정적 검사만으로 문장 정확도를 보증하지 않는다.
- 12개 개발용 문장 의미 오류 사례를 준비했으며 전문가 검토 전이다. 실제 정확도/99% 평가 자료가 아니다.
- 공식 기술 자료 후보 7개는 접속 실패/원문 미열람으로 BLOCKED/approved=false다. 승인 용어집에 넣거나 공식 용어를 확인했다고 표시하지 않았다.

## 단계별 완료 추가 근거

- 실제 빈 페이지는 직원의 명시 확인 후 처리한다. 문자·이미지·도형이 있으면 빈 페이지 선언을 거부한다. 문서 전체가 빈 경우 번역 완료로 처리하지 않는다. 확인된 빈 페이지도 원본/Word/PDF 부록에 보존한다.
- 원본 미리보기의 페이지 수·번호·SHA-256을 대조한다. 이미지 누락·변조 시 브라우저 제공/AI 문맥 전달/보고서 생성을 차단한다. 관련 2개 실패 시험을 포함했다.
- 개발 검증도 기초 → 계정/원본 → PDF → 기술 의미 보조 검사 → 전체 문서 처리 순서로 실행한다. 실패·시험 0개·건너뜀·예상 실패는 후속 실행을 차단한다. 실제 비정상 종료 코드 23을 발생시켜 다음 명령의 파일 생성이 실행되지 않았음을 확인했다.
- 단계별 22/7/9/19/16개, 총 73개 단위/HTTP 시험이 통과했다. 이후 실제 Chromium의 전체 흐름/빈 페이지 확인, LibreOffice 2개 문서 재열기가 통과했다. [단계별 기계 기록](evidence/stages/stage-results.json), [최종 기록](evidence/validation-summary.json).
- 지속 규칙/현재 상태/API 보류 및 재개 조건은 AGENTS.md와 docs/HANDOFF.md에 저장했다. 이는 프로젝트 내 인계 문서이며 전역 기억이나 실제 고객 문서 승인 기록이 아니다.

비API 현재 지원 범위의 구현/격리 검증은 완료했지만 공식 자료 원문 검토와 실제 고객 문서의 품질 평가는 여전히 미검증이다. 전체 실제 업무 완료 판정은 BLOCKED를 유지한다.

승인본은 검토한 본문 뒤에 최종 승인 기록을 추가한다. 원래 생성 시점 미승인 표시와 사후 승인 시점을 구분하며 전자서명이 아니다. 이전 형식의 승인에 최종 파일 해시가 없으면 다운로드를 차단하고 새 검증/승인이 필요하다. 코드 지문 변경 시 실제 모델 평가·문서 의미 검증이 재요구된다. 합성 자격을 실제 운영 DB에 등록하지 않는다.


## 비API 작업 재개 — 운영자 비밀번호 복구

사용자는 체크리스트 재확인 후 API와 무관한 작업을 나열하고 착수하라고 지시했다. API/시크릿/결제는 다시 보류하며 동일 호출을 반복하지 않는다. 최근 API 실제 호출은401이었으며 입력된 사용자 키의 오류라고 확정하지 않는다. 실행 값의 대체값 표시는 프록시 치환 방식일 수 있고 정확한 실패 위치는 미확정이다.

시작 전 기존102개 시험 및 전체 소스/증거 해시 일치를 확인해 보고했다. 비API 작업은 운영자 계정 복구·운영 안내를 이번 구현 대상으로 잡았으며, 실제 URS 대조·공식 원문 검토·실제 운영 인수는 외부 검증으로 분리했다.

| 단계 | 조건 | 상태 |
|---|---|---|
| 1 | 운영자 전용 reset-password, 숨김 입력, 기존 계정만 변경 | 구현·시험 통과 |
| 2 | 해당 직원 세션 무효화, 다른 직원·원본·검증 이력 보존 | 관련16개 시험 통과 |
| 3 | 설치·기동·재시작·비밀번호 복구·백업/복구 안내 | operations.md 저장 |
| 4 | 전체 회귀 및 증거/인계/ZIP 갱신 | 최종 검증 결과는 최신 요약 참조 |

실제 회사 계정 비밀번호는 변경하지 않았다. API를 호출하지 않았고 실제 고객 자료를 전송하지 않았다. [시험 로그](evidence/password-recovery-tests.txt) · [운영 안내](operations.md).

이번 최종 검증: **105개(22/28/9/19/27), Chromium2개 흐름, LibreOffice4개 문서 PASS**, 실행기 종료코드 모두0. 소스/증거 해시 일치. API 작업은 수행하지 않았다.
