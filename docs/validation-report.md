# 승인한 페이지별 가독성 방향을 CSS 기본값으로 적용 (2026-11-23)

최초 HTML 생성(a4-readable-layout-v5)과 수동 CSS 편집의 공통 지침·요청 미입력 기본값에 페이지별 내용량/여유 공간 분석을 반영했습니다. 적은 내용은 글자·줄 간격·문단 간격을 키워 읽기 좋게 하고 많은 내용은 별도로 조정합니다. 모든 페이지에 같은 수치를 일괄 적용하거나 빈 공간을 100% 채우지 않습니다. SG6 확인용 사본의 크기값·좌표·쪽수를 다른 문서로 복사하지 않습니다. 실제 CSS는 모델이 결정하며 프로그램에 자동 배치/분할 엔진을 추가하지 않았습니다.

A4, style 밖 원본 보존, 그림 표시, 잘림 방지와 기존 비용 한도는 유지됩니다. 저장된 프롬프트·기존 보고서·운영 DB는 변경하지 않았습니다. API 호출은 모의 시험만 수행했으며 운영 반영은 미확인입니다.

검증: 관련 단위 10개·최초 생성 단위 12개·CSS/초기 생성 브라우저 모의 시험 통과. 전체 단위·HTTP 254개와 실행기 13개 통과, 현재 소스·증거 지문 일치. 운영 적용은 미확인입니다.

- 최종 HTML의 인라인 JavaScript 및 cdnjs/jsdelivr/unpkg PDF.js/worker 실행을 분리된 sandbox에서 허용합니다. allow-same-origin은 허용하지 않으며 부모 직원 화면 접근, 폼 전송은 차단합니다. 저장된 모델 HTML bytes는 수정하지 않습니다.
- 브라우저 시험에서 실제 PDF.js 3.11.174로 로컬 선택 PDF를 읽어 페이지/빨강·파랑 원본 이미지를 캔버스 픽셀로 확인했습니다. PDF 선택 시 서버 POST가 없고 부모 화면 접근이 차단됨을 확인했습니다. 재현 시험은 Apache-2.0 배포본을 tests/vendor/pdfjs에 보관해 외부 네트워크 없이 실행합니다.
- 실제 API 응답이 HTTP 200이지만 incomplete인 경우를 별도로 기록합니다(api_http_success/api_response_completed/incomplete_reason). HTML 완료나 번역 품질 통과로 오인하지 않습니다.

- 새 JavaScript 실행 정책과 .env 변경을 실행 중인 웹 서버에 적용하려면 서버 재시작이 필요합니다. 프롬프트 DB 저장/진단 자체는 서버를 중지하지 않고 실행할 수 있습니다.

# 선택형 reasoning.effort 지원 (2026-11-16)

.env의 URS_OPENAI_REASONING_EFFORT를 보고서·독립검증·분석 API 요청의 reasoning.effort로 전달합니다. 빈 값/미설정은 기존처럼 해당 필드를 생략합니다. 앱에서 허용하는 명칭은 none/minimal/low/medium/high/xhigh이며, 각 모델의 실제 지원 여부는 실제 API 응답으로 확인해야 합니다. 임의의 기본 effort나 모델을 지정하지 않습니다.
보고서 메타데이터와 검증 근거에 effort를 기록하며 설정이 달라지면 기존 검증을 최종 승인에 재사용하지 않습니다. 기존 HTML/운영 자료는 수정하지 않습니다.
진단 CLI의 requested_effort는 실제 설정값을 표시하고 returned_effort는 API 응답 필드가 있을 때만 기록합니다.
추가 시험 3개: 보고서/검토 요청 값 전달(허용값별), 잘못된 값의 네트워크/비용 예약 전 차단, 진단의 설정 표시. 전체 현재 시험 100개. 실제 사용자 API의 모델/effort 지원은 미검증입니다.
.env 저장 후 실행 중인 서버에 적용하려면 서버 재시작이 필요합니다. .env.example은 새 빈 항목만 추가하며 기존 .env를 덮어쓰지 않습니다.

## 최종 완료에 필요한 외부 조건

1. API 연결은 사용자 지시에 따라 보류했다. 사용자가 이미 키 등록/변경을 했다고 확인했으며, 같은 키의 재입력이나 캡처를 요구하지 않는다. 실제 호출 시에는 실행 환경의 연결 조건이 충족돼야 하지만 현재 개발 작업은 이 조건을 기다리지 않고 진행한다. 보류를 API 검증 PASS로 처리하지 않는다.
2. 회사/고객이 사용을 승인한 대표 실제 URS PDF와 전문가 원문 대조 자료가 필요하다. 영어·인도네시아어, 표·그림·스캔·안전 조건 등 실제 사용 범위를 포함해야 한다.
3. 실제 OpenAI 응답으로 번역/검증/수정/분석을 실행하고, 원문 및 출력 4개를 전문가·직원이 대조한다. 전문가 평가를 현재 코드·고정 모델에 연결해 99% 이상·중대 안전 오역 0건을 입증한다.
4. 실제 문서의 미해결 오류가 0이 되고 출력 검토/직원 승인을 통과한 뒤 최종 업무 완료를 판정한다. 로컬 개발 서버 검증은 외부 배포/게시 검증이 아니다.

무선 표·특수 레이아웃·문자 없는 빈 페이지 등 현재 자동 판독으로 확정할 수 없는 문서는 검토/차단 대상으로 남는다. 위 외부 조건이 있어도 새 오류가 발견되면 수정·재시험하며 자동으로 완료라고 처리하지 않는다.


## API 연결 보류 후 후속 작업

- `120mm`처럼 단위에 붙은 숫자와 문장 끝 숫자의 변경 누락을 보강했다.

- 같은 단위의 수치를 서로 다른 제품에 바꿔 붙이는 경우, 조건/부정/의무/순서의 오역은 여전히 별도 문장 의미 검증이 필요하다. 새 결정적 검사만으로 문장 정확도를 보증하지 않는다.

## 단계별 완료 추가 근거

- 실제 빈 페이지는 직원의 명시 확인 후 처리한다. 문자·이미지·도형이 있으면 빈 페이지 선언을 거부한다. 문서 전체가 빈 경우 번역 완료로 처리하지 않는다. 확인된 빈 페이지도 원본/Word/PDF 부록에 보존한다.

- 단계별 22/7/9/19/16개, 총 73개 단위/HTTP 시험이 통과했다. 이후 실제 Chromium의 전체 흐름/빈 페이지 확인, LibreOffice 2개 문서 재열기가 통과했다. [단계별 기계 기록](evidence/stages/stage-results.json), [최종 기록](evidence/validation-summary.json).

## 고객 확인을 기술분석으로 분리 — 2026-11-23

고객 답변 대기는 번역 독립검증의 통과 조건에서 제외한다. 원문 자체의 모호성·상충 또는 명시적인 customer 항목만 이관하며, 확정 오역·누락·근거 불명 번역·프로그램 표시 문제는 계속 차단한다. 고객 확인만 남은 정상 완료 응답에는 번역 독립검증 PASS를 적용한다. 과거 모델 JSON·저장 판정은 변경하지 않고 원판정/현재 적용 정책을 구분한다. 최신 실패/진행 중 결과는 이전 결과로 우회하지 않는다.

## 한 단계씩 진행하는 직원 화면 — 2026-11-23

직원 화면을 보고서 확인 → 독립검증·문구 수정 → CSS 배치 → 최종 독립검증 → 기술분석 → 직원 승인, 여섯 화면으로 나눴다. 동시에 한 화면만 표시하고 다음/이전 화살표로 이동한다. 프로젝트 화면은 작업 중 숨기고 검토 닫기로 돌아간다. 비용·원문 파일·전체 이력은 접었으며 고급 별도 파일 검토는 일반 단계 화면에서 숨겼다. 리비전을 직원이 선택하도록 요구하지 않는다.

서버가 저장 파일·리비전·검증 시도·수정 영수증·CSS 화면 검사 결과에서 완료 조건을 계산한다. 클라이언트 체크박스로 통과를 만들지 않는다. 단계 이동 요청은 서버에서 다시 검사하며 보고서가 바뀌면 이전 화면의 요청을 거부한다. CSS 실행·기술분석 준비/실행·승인 API도 선행 단계를 검사한다. 뒤로 이동은 읽기 동작이며 API 비용이나 보고서 변경이 없다.

| 단계 | 다음 단계가 열리는 조건 |
|---|---|
| 보고서 확인 | 정상 열람 가능한 URS 저장 HTML 존재 |
| 독립검증·문구 수정 | 같은 보고서의 검증 통과, 또는 정상 완료된 검증의 번역 오류를 빠짐없이 선택 수정해 새 HTML에 저장. 미확인 번역은 계속 차단. 표시 문제는 CSS와 최종 검증에서 해결 |
| CSS 배치 | 그 수정본을 대상으로 CSS만 다듬어 새 버전 저장·A4/사진/잘림 검사 통과 |
| 최종 독립검증 | CSS가 반영된 동일 현재 버전의 최신 검증이 PASS. 이전 PASS/다른 리비전/최근 실패 우회 금지 |
| 기술분석 | 그 동일 버전의 기술분석 정상 완료·PASS |
| 직원 승인 | 기존 최종 검토·전문가 평가 근거 등 승인 기준 유지. 합성 시험으로 실제 승인을 만들지 않음 |

문구 수정 단계의 ‘완료’는 직원 수정 저장을 뜻하며 수정 전 모델 FAIL을 PASS로 고친 것이 아니다. CSS 후 최종 재검증 PASS가 필수다. 고객 확인은 기존 분리 정책대로 기술분석에 이관하며 번역 검증을 막지 않는다. CSS 대상은 최신 실패 시도가 아닌 현재 선택된 정상 저장 보고서로 고정했다.

실제 사용자 경로 시험은 tests/browser_workflow.py에서 컴포넌트 호스트 없이 한 화면 표시·서버의 건너뛰기 거부·직접 입력 수정 저장·수정된 HTML의 CSS 실행·현재 CSS 버전 재검증·기술분석·자유로운 뒤로 이동·정확한 HTML 다운로드를 확인한다. 기존 브라우저 회귀 시험은 tests/component_harness.py의 테스트 전용 컴포넌트 호스트로 기존 컨트롤/HTTP/저장 계약을 별도 검사한다. 운영에 단계 잠금을 해제하는 모드는 추가하지 않았다. 새 UI 증거는 workflow-*.png이며 과거 컴포넌트 캡처와 구분한다.

모의 검증은 임시 DB와 합성 PDF만 사용했다. 실제 유료 API는 호출하지 않았다. 운영 SG6 파일·DB·프롬프트·직원 답변을 변경하지 않았다. 외부 운영 접속/적용과 실제 고객 문서 품질은 별도 미확인이다. HTML 파일 URL은 실행 환경 관리자 정책으로 차단되므로 내려받은 정확한 파일 바이트를 오프라인·JavaScript 비활성 브라우저에 로드해 사진과 A4 크기를 측정했다. 실제 사용자 PC에서 파일 URL을 열었다고 보고하지 않는다.

추가 회귀 확인: 최신 생성 시도의 저장 파일이 실패/배치 미통과여도 현재 열람 중인 정상 저장본을 CSS 대상으로 받을 수 있도록 서버 선택 검사를 보완했다. 기존 실패본을 지우거나 현재 보고서를 다른 파일로 자동 교체하지 않는다. 테스트는 기존 버전 1과 미통과 버전 2를 보존한 채 버전 1의 CSS 수정본이 새 버전 3으로 저장되는지 확인한다.

고객 확인 질문도 CSS/직원 수정의 부모 보고서 이력을 따라 미답변 상태로 기술분석에 전달한다. 중간 버전에서 번역 지적이 사라졌다고 원문 질문을 버리지 않는다. 이관 출처를 기록하며 이전 리비전의 PASS 판정을 재사용하지 않는다. 해당 정책의 최종 추가 재검사 기록: docs/evidence/final-flow-policy-recheck.txt.

## 단계별 독립 화면으로 재구성 — 2026-11-23

사용자는 단계 표시가 있어도 다른 단계 내용이 함께 보인다고 확인했다. 종전의 모든 패널을 같은 문서에 두고 hidden 처리하던 구성을 교체했다. 초기 HTML의 단계 컨트롤은 template으로 분리하고 현재 단계만 화면 문서에 연결한다. 나머지 패널·실행 버튼·전체 기록은 분리된 메모리 조각에 보관한다. 한 단계에서 다음으로 이동하면 앞 단계 콘텐츠는 현재 화면 문서에서 빠진다. 실행 기록은 별도 읽기 링크로 제공한다.

단계 주소는 ?document=<ID>&step=1 … step=6으로 구분한다. URL 직접 입력과 브라우저 뒤로/앞으로도 기존 서버 선행 조건 검사를 거친다. 새로고침은 해당 단계로 복귀하며 추가 생성·검증·CSS 호출을 만들지 않는다. 동일 보고서에서 이전/다음으로 이동할 때 직원 승인 메모의 미저장 입력도 보존하되 보고서 버전이 바뀌면 다시 확인한다.

이전 HTML이 남은 경우에도 기존 컨트롤을 화면에서 분리하고 새 단계 화면으로 구성한다. 단계 API가 없는 이전 서버라면 업데이트·재시작 안내를 표시하고 전체 기능을 한 화면에 펼치는 방식으로 되돌아가지 않는다. 자산 URL에 새 화면 버전을 지정했다. 로그인·프로젝트 화면과 현재 단계 외의 작업 화면은 함께 표시하지 않는다.

검증은 tests/browser_workflow.py의 실제 로그인·클릭으로 현재 문서에 패널이 정확히 하나뿐인지, 다른 단계의 보고서·CSS·승인 컨트롤이 존재하지 않는지, 단계 주소/새로고침/브라우저 뒤로·앞으로/직접 주소 건너뛰기 차단/메모 보존/이전 HTML 호환/구형 API 안내를 확인한다. 기존 컴포넌트 호스트는 테스트 전용이며 운영에는 전체 단계 펼치기 모드를 추가하지 않았다. 번역·디자인·이미지 연결·비용·모델/effort/출력 한도·원본 보고서/DB/검증 기록은 변경하지 않았다.

실제 유료 호출은 없으며 임시 DB·합성 PDF·모의 응답만 사용했다. 운영 주소는 이 환경에서 GitHub 인증으로 이동(HTTP 302)하여 운영 적용을 확인하지 못했다. GitHub 소스 반영·로컬 실제 브라우저 시험·운영 확인을 구분한다.
