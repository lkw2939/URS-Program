# 개발 시작 체크리스트 및 단계 게이트

## 운영 원칙

각 단계 시작 전에 세부 체크리스트를 확정한다. 각 항목에는 ID, 원본 요구사항 ID, 필수 여부, 구현물, 시험 입력, 기대 결과, 실행 명령, 실제 결과, 근거 파일, 대상 리비전, 검토자를 기록한다. 실행 전 상태는 UNVERIFIED이며 미구현 기능은 NOT_IMPLEMENTED다.

필수 항목 전부 PASS이고 이전 단계도 PASS인 경우에만 서버가 다음 정식 단계 실행을 허용한다. UI 버튼 차단만으로 구현을 완료하지 않는다. FAIL / NEEDS_REVIEW / UNVERIFIED / BLOCKED / NOT_IMPLEMENTED는 모두 진행 차단이다. API 호출 성공이나 파일 생성만으로 PASS를 주지 않는다. 예외 통과 기능은 만들지 않는다. 개발용 격리 시험은 정식 결과와 구분한다.

수정 시 문서 리비전을 올리고 관련 검증·후속 분석·보고서·승인을 무효화한다. 의존 관계가 불명확하면 후속 전체를 무효화한다. 서버는 최신 리비전을 기준으로 실행 직전과 결과 저장 직전에 게이트를 검사한다. 검증 결과는 서버의 검사기만 기록하고 직원은 사람이 담당하는 검토 항목만 완료할 수 있다. 자동 수정은 횟수·비용 제한을 초과하면 NEEDS_REVIEW로 끝낸다.

PASS는 명시한 시험 범위 안에서 입증한 결과다. 모든 가능한 PDF 또는 번역의 무오류 보장이 아니다. 의미 정확도 99% 이상·중대한 안전 오역 0건은 전문가가 검토한 평가집으로 측정할 품질 목표이며, 근거 전에는 달성을 표시하지 않는다.

전체 요구사항은 유지한다. 뒤 단계의 세부 체크리스트는 해당 단계 구현 전에 같은 형식으로 구체화한다. 이후 구현에 필요한 설계는 미리 할 수 있지만 이전 단계 통과 전 다음 단계 개발 완료로 기록하지 않는다.

## 1단계 검증 결과와 범위

16개 시험 통과, 실패/건너뜀 0개. 실행 명령은 `python -m unittest discover -s tests -v`, 원본 로그는 [stage1-tests.txt](evidence/stage1-tests.txt), 상세 근거는 [stage1-review.md](stage1-review.md) 참조.

S1-01~08의 PASS는 단계 통제 기반 모듈 및 내부 HTTP API의 격리 시험 범위다. 실제 직원 로그인/역할은 2단계이며 PDF·번역·보고서 검사기는 아직 미구현이다. 누락 검사기는 NOT_IMPLEMENTED로 기록되어 진행을 차단한다. S1-05는 리비전별 결과·승인 무효화를 검증했으며 실제 보고서 파일의 제공 차단은 8단계에서 추가 검증한다. S1-07은 내부 API 인증 및 자동 검사 수동 통과 차단을 검증했으며 직원 권한별 시험은 2단계에서 추가한다.

S1-09: 검증 자료를 제시한 뒤 사용자가 다시 “진행”을 지시했다. 이를 개발 진행 결정으로 기록한다. 초기 문서에 추가했던 매 단계 별도 사람 확인 절차는 개발 에이전트의 시험·근거 검토와 사용자의 진행 지시를 반영하도록 정리했다. 사용자가 시험을 직접 재실행했다거나 실제 고객 문서를 승인했다고 주장하지 않는다. 업무 단계의 필수 검증·직원 승인 통제는 유지한다. 2단계 체크리스트 및 결과는 [stage2-checklist.md](stage2-checklist.md) 참조.

## 현재 구현 진척과 최종 판정

3~9단계의 주요 코드 및 격리 시험까지 진행했다. 최신 근거와 실제 업무 검증 상태는 [validation-report.md](validation-report.md)를 기준으로 한다. 이전 단계 로그/화면은 해당 시점의 역사 자료이며 현재 전체 완료를 뜻하지 않는다.

최신 전체 재현 명령 `python scripts/validate.py`: 자동시험 48개 + Chromium 전체 흐름 + LibreOffice Word 재열기 통과. 실제 OpenAI와 실제 고객 URS의 의미/분석/출력 평가는 미실행이다. 실제 문서의 정식 단계 이동·최종 승인 게이트는 유지하며 전체 업무 완료 상태는 BLOCKED다.
