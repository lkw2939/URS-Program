# 운영자용 작업 DB 백업·복구

프로젝트 루트에서 실행한다. API 연결 없이 동작한다. 실제 작업 DB와 백업은 고객 문서와 직원 비밀번호 해시를 포함하므로 소스 코드 묶음과 구분해 보관한다. 기본 권한은 소유자만 읽고 쓸 수 있는 0600이다. 직원 웹 화면에 전체 DB를 내보내는 기능은 제공하지 않는다.

## 백업

```bash
.venv/bin/python -m urs --data .runtime/workspace.sqlite backup .runtime/backups/workspace-001.sqlite
```

SQLite 백업 API를 사용하므로 단순 파일 복사와 달리 WAL에 남은 커밋도 포함한다. 원본 DB, 보관 PDF 해시, 검증 결과 근거 해시, 검증된 보고서 파일 및 최신 추출 페이지 이미지의 개수·해시를 확인하고 새 파일에만 저장한다. 백업 파일 해시와 프로젝트/문서/이력 개수를 출력한다. 키/환경 설정은 출력하지 않는다. 기존 대상 파일에는 덮어쓰지 않는다.

## 새 경로로 복구

```bash
.venv/bin/python -m urs --data .runtime/restored-001.sqlite restore .runtime/backups/workspace-001.sqlite
.venv/bin/python -m urs --data .runtime/restored-001.sqlite serve --port 8795
```

기존 DB와 다른 새 경로에 복구한다. 기존 경로가 있으면 실패하며 파일을 지우거나 덮어쓰지 않는다. 같은 파일로 백업/복구하는 요청도 거부한다. 복구 시 이전 로그인 세션은 지우므로 직원은 기존 계정/비밀번호로 다시 로그인한다. 원본 DB와 백업 파일의 세션은 변경하지 않는다.

프로젝트·고객 원본·페이지 이미지·번역/검증/분석·Word/PDF·수정/승인 이력은 보존한다. 복구했다고 번역이 재검증되거나 새로 승인되는 것은 아니다. 코드/모델 평가 조건이 달라졌다면 기존 승인본 제공은 기존 검증 규칙에 따라 차단된다. API 키와 외부 환경 설정은 DB 백업에 포함시키지 않는다.

## 검증 근거

`tests/test_backup.py`의 12개 시험:

- 원본 바이트·프로젝트·리비전/이력 보존 및 새 로그인 필요.
- 기존 대상 파일과 원본 파일 덮어쓰기 차단.
- 잘못된 DB와 근거 해시 변조 시 실패.
- 보고서 손상·누락, 페이지 이미지 손상·누락 각각에서 백업/복구 차단 및 원본 보존.
- WAL 커밋 포함.
- 실제 CLI 백업/복구 및 덮어쓰기 시 비정상 종료 코드.
- 복구 DB로 실제 서버 시작, 로그인 후 원본 다운로드·검증 기록 조회.
- 처리 완료 문서의 Word/PDF 4개·페이지 이미지·검증 기록 해시 복구 전후 일치.

[실행 로그](evidence/backup-restore-tests.txt). 자료는 격리된 합성 프로젝트이며 실제 고객 DB 운영 복구나 실제 OpenAI 품질을 검증한 것은 아니다. 백업은 암호화 파일이 아니므로 직원 비밀번호 해시/고객 문서가 있는 원본 DB와 같은 수준으로 접근을 제한한다.
