# A4 별도 검증 대상 연결 방법 / 읽기 전용 상한 점검 (2026-11-17)

| 항목 | 상태 |
|---|---|
| 기존 SG6 리비전1·2 및 A4 파일 보존 | 변경 없음 |
| A4 검증 대상 연결 | 설계 안내만 제공, 자동 등록/교체 미실행 |
| 실제 요청 원장·현재 예산 설정 읽기 전용 도구 | 구현 / 임시 DB 시험 |
| 운영 Codespaces 원장·현재 설정 | 접근 없음, 출력 확인 전 어느 상한인지 미확정 |
| API 호출 / 예약 원장 초기화 / 예산 변경 | 없음 |

권장 연결 방법은 리비전1에서 파생된 A4 variant를 별도 검증 대상으로 등록하는 것입니다. 현재 작업 리비전2와 r1 Terra raw/final은 보존하고, A4 bytes를 새 target_id/파일 SHA-256/부모revision1/원본PDF SHA와 묶어 추가합니다. 사용자가 명시적으로 A4 대상을 선택하면 검증 화면은 그 파일의 종류·해시·원본 관계를 보여주고 결과도 target_id로 추가 저장해야 합니다. 기술분석은 같은 대상의 독립검증 PASS를 요구해야 하며 과거 Terra 원본 검증을 A4 통과로 재사용하면 안 됩니다. 기존 review_pdf의 raw HTML 고정 입력과 결과 화면의 하드코딩된 입력 설명을 이 선택과 함께 수정하는 작업이 필요합니다. 이번 요청에서는 방법만 안내하고 구현·등록·리비전 이동·자동 생성하지 않습니다.

scripts/inspect_ai_limits.py는 Workspace 초기화 없이 sqlite mode=ro/query_only로 실제 ai_usage의 모든 상태별 요청 수·reserved 합계와 현재 직원 web max_output_tokens, 현재 CLI 환경 우선/current .env의 허용된 숫자 설정만 읽습니다. 모델 호출이나 AI 비용 예약 행 삽입/초기화/실패 예약액 반환은 없습니다. 키/프롬프트/HTML/PDF 본문을 출력하지 않습니다.

SG6 확인 명령: python scripts/inspect_ai_limits.py --document c839d7d19540a8cbdd43811b4e151112 --revision 1

현재 리비전2에 raw HTML이 없으므로 --revision 1은 계산할 기존 검토 입력을 명시하는 옵션일 뿐, 현재 리비전이나 검토 대상을 바꾸지 않습니다. 실제 저장 파일 크기와 현재 review_pdf 지시 원문의 byte 수, 현재 출력 한도로 생산용 예약 산식을 그대로 계산합니다. request_count_limit_reached / budget_limit_for_target을 분리해서 출력합니다. 둘 다 제한일 수도 있습니다. raw가 없으면 예약 계산은 null이며 추측하지 않습니다.

중요 한계: 현재 셸 환경/현재 .env는 이미 실행 중인 서버나 과거 실패 시점의 환경 스냅샷과 다를 수 있습니다. 기존 일반 FAIL에는 당시 count/reserved/budget이 저장되지 않았으므로 이 도구만으로 과거 원인을 확정 복원하지 않습니다. 현재 설정으로 같은 입력을 요청할 때 어떤 상한이 걸리는지 실제 원장과 대조합니다. PDF byte 수 기반 예약액은 실제 토큰·청구액이 아닙니다. 실패/진행 중 예약액도 합계에 포함됩니다.

시험은 요청 수만 초과 / 예약 예산만 초과 / 없는 현재 리비전 입력을 자동 전환하지 않음 / 운영 호출 지시와 일치 / DB·.env 바이트 보존 및 비밀 비출력을 확인합니다. 총 단위/HTTP161개 및 기존 브라우저 검증은 docs/evidence/validation-summary.json에 기록합니다. 운영 원장 데이터는 소스 ZIP/저장소에 포함하지 않습니다.

# 보고서 API 대기시간 / 비동기 웹 접수 / 안전한 실패 기록 (2026-11-17)

`--call`을 붙이면 저장 프롬프트/PDF/API 설정이 있는 경우에만 생산용 report 코드와 실제 OpenAI 어댑터로 최대 1회 호출합니다. 호출 비용은 기존 문서별 한도/사용량 원장에 기록합니다. 실제 응답 모델/effort/HTTP 상태/usage를 기록하며, 생성 결과는 새 비공개 진단 디렉터리에만 보관합니다. 기존 보고서와 단계 결과는 변경하지 않습니다.
현재 코드에는 reasoning.effort 지정이 없습니다. 실제 기본 effort는 공급자가 응답에서 반환하지 않으면 미확인으로 남깁니다. 모델은 기존 URS_OPENAI_MODEL을 그대로 사용합니다.

승인본은 검토한 본문 뒤에 최종 승인 기록을 추가한다. 원래 생성 시점 미승인 표시와 사후 승인 시점을 구분하며 전자서명이 아니다. 이전 형식의 승인에 최종 파일 해시가 없으면 다운로드를 차단하고 새 검증/승인이 필요하다. 코드 지문 변경 시 실제 모델 평가·문서 의미 검증이 재요구된다. 합성 자격을 실제 운영 DB에 등록하지 않는다.


## 비API 작업 재개 — 운영자 비밀번호 복구

사용자는 체크리스트 재확인 후 API와 무관한 작업을 나열하고 착수하라고 지시했다. API/시크릿/결제는 다시 보류하며 동일 호출을 반복하지 않는다. 최근 API 실제 호출은401이었으며 입력된 사용자 키의 오류라고 확정하지 않는다. 실행 값의 대체값 표시는 프록시 치환 방식일 수 있고 정확한 실패 위치는 미확정이다.

시작 전 기존102개 시험 및 전체 소스/증거 해시 일치를 확인해 보고했다. 비API 작업은 운영자 계정 복구·운영 안내를 이번 구현 대상으로 잡았으며, 실제 URS 대조·공식 원문 검토·실제 운영 인수는 외부 검증으로 분리했다.

| 단계 | 조건 | 상태 |
|---|---|---|
| 1 | 운영자 전용 reset-password, 숨김 입력, 기존 계정만 변경 | 구현·시험 통과 |
| 2 | 해당 직원 세션 무효화, 다른 직원·원본·검증 이력 보존 | 관련16개 시험 통과 |
| 3 | 설치·기동·재시작·비밀번호 복구·백업/복구 안내 | operations.md 저장 |
| 4 | 전체 회귀 및 증거/인계/ZIP 갱신 | 최종 검증 결과는 최신 요약 참조 |

실제 회사 계정 비밀번호는 변경하지 않았다. API를 호출하지 않았고 실제 고객 자료를 전송하지 않았다. [시험 로그](evidence/password-recovery-tests.txt) · [운영 안내](operations.md).

이번 최종 검증: **105개(22/28/9/19/27), Chromium2개 흐름, LibreOffice4개 문서 PASS**, 실행기 종료코드 모두0. 소스/증거 해시 일치. API 작업은 수행하지 않았다.
