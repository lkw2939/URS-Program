# 실제 전문가 평가 근거 형식

현재 모델/코드로 실제 URS 번역과 검증을 실행하고, 전문 검토자가 원문과 출력물을 대조한 자료를 입력한다. AI 자체의 PASS, 고정 응답 시험, 단순 숫자 일치만으로 사람의 의미 평가를 대체하지 않는다. 스캔·표·그림·안전/부정/조건/의무/수치/제품 코드가 포함된 대표 사례를 구성한다.

최소 100개 고유 ID/원문, 영어(en)와 인도네시아어(id) 모두 필요하다. 각 사례에는 원문·기대 의미·실제 관측 번역·사람의 판정·중대 기술/안전 오역 여부·출처 및 검토 근거를 포함한다. 모델/프롬프트 변경 후 이전 평가를 재사용하지 않는다. 추가 문서가 통과했다고 기존 실패를 삭제해 점수를 높이지 않는다.

아래는 **형식 설명용 불완전 예시**이며 실제 평가 근거가 아니다. 이 한 항목만으로는 등록할 수 없다.

```json
{
  "reviewer": "실제 기술 전문가 검토자",
  "samples": [
    {
      "id": "case-001",
      "language": "en",
      "source": "실제 원문",
      "expected_meaning": "전문가가 확정한 기술적 의미",
      "observed_translation": "검증 대상 모델의 실제 출력",
      "verdict": "PASS",
      "critical_error": false,
      "evidence": "실제 문서/페이지/요구사항 ID와 대조 근거"
    }
  ]
}
```

`verdict`는 PASS/FAIL, `critical_error`는 true/false. 의미가 틀리면 FAIL로 기록하고 중대 안전 오역이면 반드시 true로 기록한다. 집계는 PASS/전체 항목 비율이며 99% 이상·중대 오역 0건을 통과해야 자격이 생긴다. 현재 시스템은 검토자가 참으로 판정한 근거를 보관하는 도구이며 전문가의 판단 자체를 대신하지 않는다. 등록은 서버 운영자 CLI만 제공하며 직원 화면/API에서 가짜 자격을 생성할 수 없다.

현재 앱은 이 평가집을 코드 지문·설정 모델 ID에 연결해 보관한다. 실제 모델 ID와 평가 실행 근거의 정합성은 운영자가 확인해야 한다. 모델 별칭이 바뀔 수 있으므로 고정 버전 모델 사용을 권장한다. 평가 자격은 해당 문서의 최종 승인이나 새로운 문서에서의 무오류 보장이 아니다.

최신 사용자 기준: 문장 전체의 기술적 의미가 용어별 일치율보다 우선한다. 용어 오류가 문장에 미친 영향을 함께 판정한다. 용어 점수와 문장 의미 점수는 분리하며, 높은 단어 점수로 문장 오류를 상쇄하지 않는다. 공식 출처의 용어집을 참조하되 기술 문맥과 원문의 명시적 요구가 우선이다. 문서 단위로 개발용/독립 평가용을 나누고 평가 정답이 용어집·프롬프트로 유입되지 않게 한다.
