# 공식 기술 용어와 문장 의미 우선 원칙

사용자가 회사 승인을 받았다고 명시했다. 같은 승인을 반복 요청하지 않는다. 실제 API 키는 보안 설정으로 받고 채팅에 요청하지 않는다.

최우선 판정은 문장 전체의 기술적 의미다. 용어의 정확성은 그 의미를 지키기 위한 필수 요소이며, 단어가 맞아도 부정·조건·요구 수준·순서·대상 관계가 틀리면 FAIL이다. 용어 점수와 문장 의미 점수를 분리하고, 용어 점수의 평균으로 문장 의미 정확도를 대신하지 않는다. 기존 전문가 평가의 PASS/FAIL은 문장 전체 기술 의미 판정이다.

공식 자료 활용은 모델의 가중치를 새로 학습시켰다는 뜻이 아니다. 출처가 검토된 용어·정의·적용 문맥을 번역/검증 시 참조하도록 하는 방식이다. 실제 파인튜닝은 현재 하지 않았으며, 공식 문서를 이미 수집·검토했다고 주장하지 않는다.

자료 선정 대상:
- 한국: KS/국가표준 용어 및 해당 기계 분야의 한국산업안전보건공단 기술 지침, 원 제조사의 한국어 기술 매뉴얼.
- 미국: 해당 분야 ANSI/ASME/CEMA 등 적용 표준과 원 제조사의 영어 기술 매뉴얼.
- 공구·자동화 부품: 제조사 공식 영문/국문 카탈로그의 모델·정의·사용 문맥.

이 목록은 향후 검토 대상이며, 모든 자료가 한영 대응 표준이거나 무료 원문이라는 뜻이 아니다. 표준은 문서명·판본·조항·적용 장비/시장과 열람 권한을 확인한다. 제조사 용어를 국가 공인 표준처럼 표시하지 않는다. 사내 관용어는 별도 구분한다. 문서 이름이나 URL만으로 내용 검증을 완료 처리하지 않는다.

검토자는 `.runtime/terminology.json`에 entries 배열을 등록한다. 각 항목은 english, korean, context, organization, document, edition, location, url(HTTPS), reviewer, scope(standard/manufacturer/company), approved(true)를 포함해야 한다. 승인에는 실제 원문 열람과 한영 의미/적용 범위 확인이 선행해야 한다. 키나 비밀번호는 포함하지 않는다.

현재 해당 파일/공식 자료는 미등록이다. 앱은 UNVERIFIED로 명시하고 공식 근거가 확인되지 않은 용어를 공인 용어라고 주장하지 않도록 요청한다. 잘못된 승인 파일은 AI 실행을 차단한다. 등록된 자료는 모델에 참고 문맥으로 전달되므로 회사가 사용·전송을 승인한 범위의 인용/정의만 저장한다. 권리 확인 없이 유료 표준 전체를 복제하지 않는다.

용어집 내용이 바뀌면 코드/모델 평가 자격의 지문이 달라져 최종 승인 전에 재검증이 필요하다. 본 기능은 검토자가 입력한 출처 정보를 참조하는 구현이며, 외부 사이트의 진위·최신 판본을 자동 검증하는 기능은 아니다.

실제 URS가 여러 개 제공되면 문서 단위로 개발/용어 정리용과 최종 평가용을 구분한다. 최종 평가 문서의 정답 번역을 용어집·시험 응답에 넣은 후 같은 문서를 독립 정확도 근거로 제시하지 않는다. 평가용 문서에도 공식 외부 기술 자료의 용어집은 적용할 수 있으나, 그 판본과 용어집 지문을 고정해 평가 조건에 기록한다.

## 이번 진행 상태

API 시크릿 연결은 사용자 지시로 보류했다. 별도로 공식 사이트 원문 접근을 시도했으나 HTTPS 연결 실패/OSHA HTTP 403이 관찰됐다. 출처 후보 7개는 `docs/terminology-source-candidates.json`에 BLOCKED/approved=false로 보관했다. 내용·판본을 확인하지 않았으므로 AI용 승인 용어집에는 등록하지 않는다. 참조 목록 작성과 실제 공식 용어 대조 완료는 구분한다.

문장 의미 오류를 구체화한 `docs/evaluation/sentence-cases.json`은 개발용 초안이다. 부정·조건·의무·순서·설비별 수치 연결·단위 변경을 포함하며 전문가 검토 전이다. 이 자료를 99% 실제 정확도 평가집으로 제출하거나 고객 URS 검증 완료 근거로 사용하지 않는다.

## 운영자 검사·등록 절차

```bash
.venv/bin/python -m urs check-terminology 검토완료용어집.json
.venv/bin/python -m urs import-terminology 검토완료용어집.json
```

먼저 검사 명령이 성공해야 등록한다. 입력은 위 스키마의 entries JSON이며, 각 항목의 원문·한영 용어·문맥·기관·문서·판본·위치·HTTPS 출처·검토자·범위와 approved=true가 필요하다. 이 명령은 메타데이터를 검사할 뿐 원문을 열람하거나 전문가 대신 용어를 승인하지 않는다. 실제 검토가 끝나지 않은 자료에 approved=true를 쓰지 않는다.

등록은 검증한 동일 바이트를 비공개 임시 파일에서 원자적으로 게시한다. 기존 .runtime/terminology.json이 있으면 덮어쓰기를 거부한다. 기존 파일 교체는 운영자가 백업과 실제 검토를 거친 별도 관리 작업이다. 등록 성공 결과는 항목 수·해시·평가 재실행 필요 여부만 출력하며 실제 번역 품질 인증은 아니다. 변경 후 코드/용어 지문이 달라져 기존 전문가 평가 자격은 재평가가 필요하다. 검사/등록 명령은 외부 API를 호출하거나 작업 DB를 생성하지 않는다.
