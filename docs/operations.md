# 로컬 운영자 실행·복구 안내

현재 지원 범위는 루프백 서버다. 실제 사내 네트워크/HTTPS 배포와 회사 직원 인수는 미검증이며, 이 안내로 공개 배포가 완료됐다고 간주하지 않는다.

## 순서별 체크리스트

| 순서 | 작업 | 확인 조건 |
|---|---|---|
| 1 | 설치 | Python3.12·고정 requirements.lock 설치, pip check 성공 |
| 2 | 계정 | 운영자가 숨김 입력으로 직원 생성, 기본 계정 없음 |
| 3 | 기동 | 아래 명령 실행 후 로그인·프로젝트·원본 다운로드 확인 |
| 4 | 재시작 | 정상 종료 후 같은 --data 경로로 재기동, 기존 자료 유지 |
| 5 | 비밀번호 분실 | 로컬 운영자 CLI에서 복구, 해당 직원 재로그인 |
| 6 | DB 장애 | 기존 DB 보존, 백업을 새 경로에 복구·재로그인·원본/근거 확인 |

프로젝트 루트에서 다음 명령을 실행한다. 비밀번호를 인자·소스·로그에 넣지 않는다.

```bash
.venv/bin/python -m pip check
.venv/bin/python -m urs --data .runtime/workspace.sqlite add-user 직원ID
.venv/bin/python -m urs --data .runtime/workspace.sqlite serve --port 8795
```

서버 종료는 실행 터미널에서 Ctrl+C다. 다시 같은 serve 명령을 사용한다. 사용자 비밀번호와 실제 고객 데이터를 이 문서에 기입하지 않는다.

## 직원 비밀번호 복구

```bash
.venv/bin/python -m urs --data .runtime/workspace.sqlite reset-password 직원ID
```

새 비밀번호를 숨김 입력으로 두 번 입력한다(12~256자). 존재하는 계정만 변경하며 새 계정을 만들지 않는다. 해당 직원의 기존 세션과 실패 횟수를 지운다. 다른 직원 세션, 프로젝트, 원본, 검증/승인 기록은 보존한다. 운영 DB 파일을 다룰 권한이 있는 운영자만 실행한다. 웹 비밀번호 초기화 경로는 제공하지 않는다. 현재 사용자의 실제 비밀번호는 이번 개발 작업에서 바꾸지 않았다.

## 백업·복구

[백업·복구 안내](backup-restore.md)의 새 경로 원칙을 준수한다. 백업/원본DB/저널은 고객 자료와 비밀번호 해시를 포함하므로 소스 ZIP과 분리한다. 복구 후에는 로그인과 원본 바이트·검증 기록·산출물 해시를 확인한다.

## 실제 운영 인수에 남은 조건

실제 설치 장비, 접속 경로, 접근 권한, 백업 보관 위치/책임, 실제 문서 처리 범위와 직원 검토 담당을 확정하고 실제 직원이 확인해야 한다. 합성 시험은 실제 운영 인수를 대신하지 않는다. API 연결 작업은 사용자 지시로 별도 보류한다.

## 검토된 기술 용어 자료 등록

[용어 정책](terminology-policy.md)의 검사→등록 순서를 따른다. 원문을 실제 검토한 자료만 등록한다. 후보 자료는 등록하지 않으며 이 작업에서 실제 운영 용어집을 생성하지 않았다. 변경하면 기존 모델 평가 자격을 다시 확인해야 한다.
